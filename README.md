# 物体绕流的流动轨迹可视化

用 numpy 求解二维不可压缩 Navier–Stokes 方程，让来流绕过浸没固体（圆柱 / 方块 / 椭圆），
把示踪粒子的运动轨迹与涡度场导出成紧凑数据；浏览器端既可以直接播放 Python 算好的结果，
也可以在一个可拖拽的交互面板里实时求解——两种用法共用同一套离散格式。

| 部分 | 职责 |
| --- | --- |
| `fluid/solver.py` | 数值求解器（平流、扩散、压力投影、浸没固体、示踪粒子） |
| `fluid/run_sim.py` | 命令行入口：跑模拟、算诊断量、导出可视化数据 |
| `web/fluid-sim.js` | 求解器的 JavaScript 移植，供交互面板在浏览器里实时计算 |
| `web/index.html` | **交互实验台**：拖拽障碍物、调流体参数、实时诊断、导出 PNG / Python 命令 |
| `web/replay.html` | 回放器：只读 Python 算好的结果，不做物理计算（数值最准，画质最好） |
| `web/flow_data.js` | 导出结果（已提交，克隆仓库后直接打开页面就能看到） |

## 一分钟上手

```bash
# 1) 直接看：双击 web/index.html（交互实时算）或 web/replay.html（播放 Python 结果）
#    file:// 下就能跑，不需要起服务器

# 2) 自己换参数重算（约 25 秒）
py fluid/run_sim.py

# 3) 换物体形状与雷诺数
py fluid/run_sim.py --shape square --re 120
py fluid/run_sim.py --shape ellipse --size 14 --ratio 0.3 --angle 20
py fluid/run_sim.py --re 800 --nx 320 --ny 180 --size 16
```

回放页只是播放器，改参数必须重跑 `run_sim.py`；交互页能自己算，但精度和画质不如 Python 版。

## 交互实验台（`web/index.html`）

打开就是一个在跑的圆柱绕流。左边画布、右边面板：

- **拖动障碍物**：按住物体拖走；拖它的边缘圈或滚轮改尺寸；双击空白处添加一个新物体；
  `Delete` 删除选中的物体。支持多个物体（双圆柱、串列、错列都可以摆）。
- **形状**：圆 / 方 / 椭圆，椭圆可调短长轴比与迎角。
- **流体性质**：雷诺数（对数滑块 20–2000）、来流速度 `u∞`、时间步长 `dt`、
  压力 Poisson 迭代数、涡度约束强度 `eps`；网格分辨率三档（128×76 / 168×100 / 224×132）。
- **诊断**：物理时间、单步耗时与帧率、投影前后散度 RMS、`|u|max/u∞`、
  尾流探针波动、实时 Strouhal 数，以及一句"尾流是否已经定型"的状态提示。
- **每个参数都是热更新**：改 Re 只改 `ν`，改尺寸会同时改 `D`（Re 保持不变），
  拖动物体时掩膜每帧重建，不需要重新加载页面。
- **交给 Python 复算**：面板底部按当前参数生成等价命令行，复制即可在仓库根目录执行，
  用精度更高的 Python 版出正式结果。
- **复制链接**：把整套配置编码进 URL `#hash`，刷新或分享都能还原同一个实验。
- **每帧物理步数**：1× 是实时可视化（一帧一步，60 fps），8× 用来快速把尾流"跑定型"。

浏览器里跑的是 `fluid-sim.js`，它和 `solver.py` 是同一套离散格式（半拉格朗日平流、
隐式粘性、出流压力 Dirichlet、限幅涡度约束、浸没固体），**唯一区别是压力与隐式粘性
的线性求解用逐点 Gauss-Seidel 而不是 masked-Jacobi**。两者不动点相同
（固体邻点替换成中心值，等价于 `(Σ有效邻点 − div)/n有效`），但 GS 收敛快得多，
所以浏览器里 40 次迭代就能把散度压下去。同参数对比（224×132，Re = 300，60 次迭代）：

```
                  St        |u|max/u∞      div_rms 投影前 → 后
Python (Jacobi)   0.240     1.89          9.9e-03 → 3.7e-03
JS (Gauss-Seidel) 0.236     1.95          5.8e-03 → 3.0e-03
```

差异在几个百分点内，量级和趋势一致；需要写进报告的精确数字仍以 Python 版为准。
面板上的 St 是"当前网格、当前时刻"的实时估计，粗网格（128×76 / 168×100）算出的 St
会比精细网格低 10% 左右（168×100 约 0.21，224×132 约 0.24）——网格粗了，涡街的
有效雷诺数也跟着低，这是格式本身的趋势，不是 bug。

## 数学模型

无量纲化之后求解二维不可压缩 Navier–Stokes：

```
∇·u = 0                          (质量守恒)
∂u/∂t + (u·∇)u = -∇p + (1/Re)∇²u  (动量守恒)
```

长度以网格间距 `h = 1` 计，速度以来流 `u∞` 计，物体特征尺寸 `D = 2·size`，
于是 `Re = u∞·D/ν`，程序按给定的 Re 反解出 `ν`。

边界条件：左边界 `u = u∞, v = 0`（均匀入流），右边界零梯度出流，
上下边界自由滑移（`v = 0`，法向速度为零但保留切向滑移），固体内部 `u = v = 0`（无滑移）。

## 数值方法：投影法（pressure correction）

每一步分四段，这是 Chorin 投影法的标准拆分。设 `u*` 为中间速度：

1. **半拉格朗日平流**：沿特征线向后追踪 `x - dt·u*`，对旧场做双线性插值。
   该格式对任意 `dt` 稳定（无条件稳定），代价是带一阶数值粘性。
   数值粘性约为 `u∞·h·(1-CFL)/2`，**因此取 CFL = u∞·dt/h ≈ 1 最省耗散**，
   这就是默认 `dt = 1.0` 的原因，而不是随便选的。
2. **粘性扩散**：解 `(I - ν·dt·∇²)w = w*` 的 Jacobi 迭代（隐式，不受 `ν·dt/h² ≤ 1/2` 限制）。
3. **涡度约束**：`f ∝ N × ω`，`N = ∇|ω|/|∇|ω|`，把平流抹掉的小尺度涡"顶"回去。
4. **压力投影**：解 Poisson 方程 `∇²p = ∇·u*`，再令 `u = u* - ∇p`，得到无散场。

### 两个踩过的坑（值得写进报告）

**出流必须给压力 Dirichlet 条件。** 一开始入流、出流、上下壁全用 Neumann
（`∂p/∂n = 0`，靠数组四周复制边界值实现），结果投影后散度反而比投影前更大：

```
div_rms 投影前 7.9e-03 -> 投影后 3.2e-02      # 错的
```

原因是纯 Neumann 的 Poisson 问题有相容性条件 `∫∇·u = ∮∂p/∂n = 0`；
而我们固定了入流速度、尾流又让出流通量与之失衡，方程根本无解，迭代只能停在残差上。
改成出流 `p = 0`（每步把最后一列压力钉为 0）后立刻正常。

**涡度约束项必须限幅。** Fedkiw 原始形式 `f = ε·h·(N × ω)` 的力按 `1/dt` 放大，
在 `dt ≈ 1` 的设置下直接把速度推爆：

```
eps=1.5 -> |u|/u∞ = 494       eps=3.0 -> 溢出到 1e55
```

这里把它归一化成"每步速度增量不超过 `eps·u∞`"，`eps` 的可用范围变成 `[0, 0.3]`，
与 `dt`、网格分辨率解耦。`solver.py` 里 `step()` 会检查速度是否有限，
发散时直接报错而不是给出 NaN 结果。

### 浸没固体的处理

固体用布尔掩膜表示（staircase 近似边界）。速度场在固体内始终置零，
于是中心差分的散度会把"界面处质量通量被截断"这件事自动算进源项；
压力迭代时把固体邻点替换成中心值，等价于在物面施加 `∂p/∂n = 0`。

这是最简单可行的做法，代价是物面通量只有一阶精度——见"已知局限"。

### 示踪粒子

粒子是被动标量（不反馈给流体），用二阶 Runge–Kutta（中点法）积分 `dx/dt = u`，
每隔 `record_every` 步存一个点，出域 / 进入固体 / 在滞止区待太久即回收并在入流边界重新播种。

注意：**非定常流里轨迹线（pathline）≠ 流线（streamline）**。
本程序画的是轨迹线——粒子真实走过的路径；
定常流两者才重合。卡门涡街下拖尾被卷进涡里形成的螺旋，正是轨迹线的特征。

脱落频率用尾流中心线横向速度探针估计，取相邻过零间隔的中位数（半周期）。
不用 FFT：记录窗口只有几个周期，FFT 会把窗函数最低的 bin 当成主峰，给出假的低频解。

## 导出格式

`web/flow_data.js` 里是一个 `window.FLOW_DATA` 全局变量。之所以用 `.js` 而不是 `.json`：
`file://` 下 `fetch()` 会被 CORS 拦掉，而 `<script src>` 不受影响，双击就能看。

数据用 **int16 定点编码 + base64**：涡度场和轨迹点如果按十进制写进 JSON 会有上百万个数
（几十 MB），量化到 `[-32767, 32767]` 后整份数据约 1.3 MB（`--record-every 2` 的默认精度）。解码公式：

```
t = q / 32767                       # 回到 [-1, 1]
value = lo + (t + 1)/2 · (hi - lo)  # 区间记在 meta.path_ranges / meta.wmax
```

`meta.t0` 记录每条轨迹的起始时刻，播放器据此决定这条线什么时候开始出现——
否则所有轨迹都会从第 0 帧一起画出来，时间上是错的。

## 结果验证

默认参数（圆柱，Re = 300，224×132）跑出来的诊断量：

```
St = 0.240                    文献值：圆柱高 Re 段 St ≈ 0.21，偏差 14%
|u|/u∞ = 1.89                 势流绕圆柱表面理论峰值 2.00，未超上界
div_rms 投影前 9.9e-03 -> 投影后 3.7e-03
```

Strouhal 数和速度峰值都落在理论值附近，说明求解器行为是对的。
`web/replay.html` 右侧面板会显示这些数字，换参数后重跑会自动更新；
交互页的面板则实时显示同一组诊断量。

## 播放的流畅度

回放页要做到 60 fps，靠的不只是"多画几帧"，三件事缺一不可：

1. **数据采样加密**：`--record-every 2`（每 2 个时间步一个轨迹点）、`--frame-every 6`，
   轨迹和涡度场的时间分辨率都提高一倍。
2. **播放头是小数**：`Tf` 按物理时间连续推进，粒子头在相邻两个记录点之间线性插值，
   运动是连续的而不是一格一格跳；涡度帧在相邻两帧之间做像素级叠化（`drawField`）。
3. **已完成的轨迹段烘焙成静态图层**：跑完的粒子轨迹不会再变，一次性画进
   `staticCv`，之后每帧只 `drawImage` 一次。否则到片尾每帧要重画十几万个点，
   实测帧率会掉到 30 fps 以下；烘焙后无论播放到哪一帧，单帧成本都稳定在 6 ms 左右。

## 已知局限

诚实说清楚，报告里被问到不至于没话说：

1. **界面通量只有一阶精度。** collocated 网格 + 阶梯近似物面，
   物面速度取流体值与固体零值的中心平均，等于允许一点点"漏流"。
   残差散度因此停在 `3.7e-03` 量级，把 `--iters` 加到 100、120 也不会再降——
   这是离散格式的天花板，不是迭代没收敛。彻底解决要换 MAC 交错网格或贴体网格。
2. **数值粘性不可忽略。** 半拉格朗日格式一阶精度，有效 Re 低于设定 Re。
   涡度约束只能补偿部分，所以涡街比真实高 Re 流动更"糊"。
3. **二维、层流、无湍流模型。** 真实 Re > 2000 的尾流是三维且转捩的（A 模式不稳定性），
   本程序不描述那个物理。
4. **示踪粒子不反馈流体**，即假设粒子密度与流体一致、无惯性（Stokes 数 = 0）。
5. **涡度色标削顶**：`ωmax` 取第 99.5 百分位，物面附近更强的涡量被截色显示。

## 页面操作

**交互页 `web/index.html`**：左键拖动障碍物移动，拖边缘圈或滚轮改尺寸，双击空白加物体，
`Delete` 删物体，空格暂停/继续，`→` 单步。右侧面板的参数全部即时生效。
"导出 PNG" 把当前画面存成图片，"复制链接"把配置写进 URL，"复制命令"拿到等价的 Python 命令行。

**回放页 `web/replay.html`**：空格播放/暂停，左右方向键单步。滑块：拖尾长度
（45% 像彗尾，100% 显示完整路径）、背景场（涡度 / 无）、轨迹与粒子开关。
"导出当前画面 PNG" 直接把 canvas 存成图片，换一帧再导就是一组不同时刻的对比图，可直接插进报告。
