# 物体绕流的流动轨迹可视化

用 numpy 求解二维不可压缩 Navier–Stokes 方程，让来流绕过浸没固体（圆柱 / 方块 / 椭圆），
把示踪粒子的运动轨迹与涡度场导出成紧凑数据，再由 `web/index.html` 播放。

计算内核与显示分离：

| 部分 | 职责 |
| --- | --- |
| `fluid/solver.py` | 数值求解器（平流、扩散、压力投影、浸没固体、示踪粒子） |
| `fluid/run_sim.py` | 命令行入口：跑模拟、算诊断量、导出可视化数据 |
| `web/index.html` | 播放器：只读 Python 算好的结果，不做任何物理计算 |
| `web/flow_data.js` | 导出结果（已提交，克隆仓库后直接打开页面就能看到） |

## 一分钟上手

```bash
# 1) 直接看现成结果：双击 web/index.html 即可（无需服务器，file:// 就能跑）

# 2) 自己换参数重算（约 25 秒）
py fluid/run_sim.py

# 3) 换物体形状与雷诺数
py fluid/run_sim.py --shape square --re 120
py fluid/run_sim.py --shape ellipse --size 14 --ratio 0.3 --angle 20
py fluid/run_sim.py --re 800 --nx 320 --ny 180 --size 16
```

改完参数必须重跑 `run_sim.py`，页面只是播放器，不能自己算。

## 数学模型

无量纲化之后求解二维不可压缩 Navier–Stokes：

```
∇·u = 0                          (质量守恒)
∂u/∂t + (u·∇)u = -∇p + (1/Re)∇²u  (动量守恒)
```

长度以网格间距 `h = 1` 计，速度以来流 `u∞` 计，物体特征尺寸 `D = 2·size`，
于是 `Re = u∞·D/ν`，程序按给定的 Re 反解出 `ν`。

边界条件：左边界 `u = u∞, v = 0`（均匀入流），右边界零梯度出流，
上下边界自由滑移（`v = 0`，法向速度为零但保留切向滑移），固体内部 `u = v = 0`（无滑移）。

## 数值方法：投影法（pressure correction）

每一步分四段，这是 Chorin 投影法的标准拆分。设 `u*` 为中间速度：

1. **半拉格朗日平流**：沿特征线向后追踪 `x - dt·u*`，对旧场做双线性插值。
   该格式对任意 `dt` 稳定（无条件稳定），代价是带一阶数值粘性。
   数值粘性约为 `u∞·h·(1-CFL)/2`，**因此取 CFL = u∞·dt/h ≈ 1 最省耗散**，
   这就是默认 `dt = 1.0` 的原因，而不是随便选的。
2. **粘性扩散**：解 `(I - ν·dt·∇²)w = w*` 的 Jacobi 迭代（隐式，不受 `ν·dt/h² ≤ 1/2` 限制）。
3. **涡度约束**：`f ∝ N × ω`，`N = ∇|ω|/|∇|ω|`，把平流抹掉的小尺度涡"顶"回去。
4. **压力投影**：解 Poisson 方程 `∇²p = ∇·u*`，再令 `u = u* - ∇p`，得到无散场。

### 两个踩过的坑（值得写进报告）

**出流必须给压力 Dirichlet 条件。** 一开始入流、出流、上下壁全用 Neumann
（`∂p/∂n = 0`，靠数组四周复制边界值实现），结果投影后散度反而比投影前更大：

```
div_rms 投影前 7.9e-03 -> 投影后 3.2e-02      # 错的
```

原因是纯 Neumann 的 Poisson 问题有相容性条件 `∫∇·u = ∮∂p/∂n = 0`；
而我们固定了入流速度、尾流又让出流通量与之失衡，方程根本无解，迭代只能停在残差上。
改成出流 `p = 0`（每步把最后一列压力钉为 0）后立刻正常。

**涡度约束项必须限幅。** Fedkiw 原始形式 `f = ε·h·(N × ω)` 的力按 `1/dt` 放大，
在 `dt ≈ 1` 的设置下直接把速度推爆：

```
eps=1.5 -> |u|/u∞ = 494       eps=3.0 -> 溢出到 1e55
```

这里把它归一化成"每步速度增量不超过 `eps·u∞`"，`eps` 的可用范围变成 `[0, 0.3]`，
与 `dt`、网格分辨率解耦。`solver.py` 里 `step()` 会检查速度是否有限，
发散时直接报错而不是给出 NaN 结果。

### 浸没固体的处理

固体用布尔掩膜表示（staircase 近似边界）。速度场在固体内始终置零，
于是中心差分的散度会把"界面处质量通量被截断"这件事自动算进源项；
压力迭代时把固体邻点替换成中心值，等价于在物面施加 `∂p/∂n = 0`。

这是最简单可行的做法，代价是物面通量只有一阶精度——见"已知局限"。

### 示踪粒子

粒子是被动标量（不反馈给流体），用二阶 Runge–Kutta（中点法）积分 `dx/dt = u`，
每隔 `record_every` 步存一个点，出域 / 进入固体 / 在滞止区待太久即回收并在入流边界重新播种。

注意：**非定常流里轨迹线（pathline）≠ 流线（streamline）**。
本程序画的是轨迹线——粒子真实走过的路径；
定常流两者才重合。卡门涡街下拖尾被卷进涡里形成的螺旋，正是轨迹线的特征。

脱落频率用尾流中心线横向速度探针估计，取相邻过零间隔的中位数（半周期）。
不用 FFT：记录窗口只有几个周期，FFT 会把窗函数最低的 bin 当成主峰，给出假的低频解。

## 导出格式

`web/flow_data.js` 里是一个 `window.FLOW_DATA` 全局变量。之所以用 `.js` 而不是 `.json`：
`file://` 下 `fetch()` 会被 CORS 拦掉，而 `<script src>` 不受影响，双击就能看。

数据用 **int16 定点编码 + base64**：涡度场和轨迹点如果按十进制写进 JSON 会有上百万个数
（几十 MB），量化到 `[-32767, 32767]` 后整份数据 657 KB。解码公式：

```
t = q / 32767                       # 回到 [-1, 1]
value = lo + (t + 1)/2 · (hi - lo)  # 区间记在 meta.path_ranges / meta.wmax
```

`meta.t0` 记录每条轨迹的起始时刻，播放器据此决定这条线什么时候开始出现——
否则所有轨迹都会从第 0 帧一起画出来，时间上是错的。

## 参数表

| --- | --- | --- |
| `--shape` | circle | 物体形状：circle / square / ellipse |
| `--size` | 14 | 特征半径（格数），`D = 2·size` |

| `--record-every` | 4 | 每隔几步存一个轨迹点 |
| `--frame-every` | 12 | 每隔几步存一张涡度场 |

## 结果验证

默认参数（圆柱，Re = 300，224×132）跑出来的诊断量：

```
St = 0.233                    文献值：圆柱高 Re 段 St ≈ 0.21，偏差 11%
|u|/u∞ = 1.89                 势流绕圆柱表面理论峰值 2.00，未超上界
div_rms 投影前 9.9e-03 -> 投影后 3.7e-03
```

Strouhal 数和速度峰值都落在理论值附近，说明求解器行为是对的。
`web/index.html` 右侧面板会显示这些数字，换参数后重跑会自动更新。

## 已知局限

诚实说清楚，报告里被问到不至于没话说：

1. **界面通量只有一阶精度。** collocated 网格 + 阶梯近似物面，
   物面速度取流体值与固体零值的中心平均，等于允许一点点"漏流"。
   残差散度因此停在 `3.7e-03` 量级，把 `--iters` 加到 100、120 也不会再降——
   这是离散格式的天花板，不是迭代没收敛。彻底解决要换 MAC 交错网格或贴体网格。
2. **数值粘性不可忽略。** 半拉格朗日格式一阶精度，有效 Re 低于设定 Re。
   涡度约束只能补偿部分，所以涡街比真实高 Re 流动更"糊"。
3. **二维、层流、无湍流模型。** 真实 Re > 2000 的尾流是三维且转捩的（A 模式不稳定性），
   本程序不描述那个物理。
4. **示踪粒子不反馈流体**，即假设粒子密度与流体一致、无惯性（Stokes 数 = 0）。
5. **涡度色标削顶**：`ωmax` 取第 99.5 百分位，物面附近更强的涡量被截色显示。
